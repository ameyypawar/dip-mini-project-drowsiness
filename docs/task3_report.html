Experiment TitleImage Enhancement in the Spatial Domain
Aim To implement and evaluate classical spatial-domain image-enhancement techniques -- intensity transformations (negative, log, gamma, contrast stretching), histogram analysis and equalization, and image arithmetic (addition, subtraction, averaging) -- on grayscale near-infrared eye-crop images from the driver-drowsiness dataset, to quantitatively compare their effect on brightness, contrast and noise, and to identify the most suitable technique for images captured under different lighting/glare conditions.
Resources / Apparatus Required Software: Python 3.11 • OpenCV • NumPy • Matplotlib • scikit-image • Pillow • Jupyter Notebook / VS Code
Algorithm

A. Intensity Transformations

  1. Start the program.
  2. Read the grayscale eye-crop image as a NumPy uint8 array.
  3. For the negative, compute s = 255 - r for every pixel.
  4. For the log transform, compute s = c*log(1+r), with c auto-scaled to the image's own peak intensity (or supplied by the user).
  5. For gamma correction, normalize r to [0,1], compute s = c*r^gamma, rescale to [0,255]; gamma and c are user-supplied parameters.
  6. For contrast stretching, take r_min/r_max from a percentile clip of the image (or user-supplied fixed values) and linearly map [r_min, r_max] to [out_min, out_max].
  7. Clip every result to [0,255] and cast to uint8.
  8. Display the original and enhanced image side by side.
  9. Stop the program.

B. Histogram Analysis

  1. Start the program.
  2. Read the image.
  3. Compute the 256-bin intensity histogram via np.histogram.
  4. Compute summary statistics: mean, standard deviation, min, max.
  5. Plot the histogram alongside the image.
  6. Repeat steps 3-5 for an enhanced version of the same image.
  7. Compare the before/after histograms visually and via the summary statistics.
  8. Stop the program.

C. Histogram Equalization

  1. Start the program.
  2. Read the image.
  3. Compute the image histogram and its cumulative distribution function (CDF).
  4. Normalize the CDF to [0,255] using its first non-zero value as the floor.
  5. Build a 256-entry lookup table from the normalized CDF and apply it to every pixel (own implementation), or call cv2.equalizeHist (OpenCV implementation).
  6. Compare both outputs pixel-by-pixel to confirm they agree.
  7. Plot the original vs. equalized image and histogram.
  8. Record the contrast (standard deviation) before and after.
  9. Stop the program.

D. Image Arithmetic

  1. Start the program.
  2. Read one or two source images (resize the second to match the first, nearest-neighbour, if their sizes differ).
  3. For addition, compute a weighted blend alpha*img1 + (1-alpha)*img2, or add a constant brightness offset.
  4. For subtraction, compute the absolute difference |img1 - img2|.
  5. For averaging, synthesize N seeded noisy copies of the image and average them pixel-wise.
  6. Clip every result to [0,255] and cast to uint8.
  7. Display the arithmetic result and note its practical application.
  8. Stop the program.

E. Comparison

  1. Start the program.
  2. Apply every technique (negative, log, gamma x2, contrast stretch, histogram equalization) to each of the 3 test images.
  3. For every output, compute brightness (mean), contrast (standard deviation) and a noise proxy (standard deviation of the image minus its own 3x3 median filter).
  4. Normalize each technique's contrast and noise against the original image's values to get a contrast-gain and a noise-gain ratio.
  5. Score each technique as contrast_gain / noise_gain; reject any technique that pushes brightness outside [30, 225] (near-black or washed-out).
  6. Pick the highest-scoring technique per image as the most suitable and record the justification.
  7. Tabulate brightness / contrast / noise for all techniques x images.
  8. Stop the program.

A. Intensity Transformations

def negative(img):
    return (255 - img.astype(np.int16)).astype(np.uint8)

def log_transform(img, c=None):
    img_f = img.astype(np.float64)
    if c is None:
        c = 255.0 / np.log1p(img_f.max())
    return np.clip(c * np.log1p(img_f), 0, 255).astype(np.uint8)

def gamma_correction(img, gamma=1.0, c=1.0):
    norm = img.astype(np.float64) / 255.0
    return np.clip(c * np.power(norm, gamma) * 255.0, 0, 255).astype(np.uint8)

def contrast_stretch(img, r_min=None, r_max=None, low_pct=2.0, high_pct=98.0,
                      out_min=0, out_max=255):
    if r_min is None: r_min = np.percentile(img, low_pct)
    if r_max is None: r_max = np.percentile(img, high_pct)
    out = (img.astype(np.float64) - r_min) / (r_max - r_min)
    out = out * (out_max - out_min) + out_min
    return np.clip(out, 0, 255).astype(np.uint8)

B. Histogram Analysis

def compute_histogram(img, bins=256, range_=(0, 256)):
    return np.histogram(img.ravel(), bins=bins, range=range_)

def histogram_stats(img):
    return {"mean": float(img.mean()), "std": float(img.std()),
            "min": int(img.min()), "max": int(img.max())}

C. Histogram Equalization

def equalize_histogram_cv(img):
    return cv2.equalizeHist(img)

def equalize_histogram_manual(img):          # own implementation, no cv2 call
    hist, _ = np.histogram(img.ravel(), bins=256, range=(0, 256))
    cdf = hist.cumsum()
    cdf_min = cdf[cdf > 0].min()
    lut = np.round((cdf - cdf_min) / (img.size - cdf_min) * 255)
    lut = np.clip(lut, 0, 255).astype(np.uint8)
    return lut[img]

D. Image Arithmetic

def add_images(img1, img2, alpha=0.5):            # brightness boost / overlay
    img2 = _match_shape(img2, img1)
    out = alpha * img1.astype(np.float64) + (1 - alpha) * img2.astype(np.float64)
    return np.clip(out, 0, 255).astype(np.uint8)

def subtract_images(img1, img2):                  # change / motion detection
    img2 = _match_shape(img2, img1)
    return cv2.absdiff(img1, img2)

def average_images(images):                       # noise reduction
    stack = np.stack([im.astype(np.float64) for im in images], axis=0)
    return np.clip(stack.mean(axis=0), 0, 255).astype(np.uint8)

E. Comparison

def mean_intensity(img): return float(img.mean())        # brightness
def rms_contrast(img):   return float(img.std())         # contrast

def noise_proxy(img, ksize=3):
    med = cv2.medianBlur(img, ksize)
    return float((img.astype(np.float64) - med.astype(np.float64)).std())

def compare_techniques(img, techniques=None):
    techniques = techniques or DEFAULT_TECHNIQUES
    results = []
    for name, fn in techniques.items():
        out = fn(img)
        results.append(TechniqueResult(name, out, mean_intensity(out),
                                        rms_contrast(out), noise_proxy(out)))
    return results

Image arithmetic

Application -- averaging: noise reduction by combining repeated acquisitions of the same scene. This dataset has no true multi-frame burst of one eye, so N independent seeded Gaussian-noisy copies were synthesized and averaged. Noise proxy: single noisy frame 19.40 → average of 5 frames 8.71 → average of 20 frames 4.43 -- closely tracking the theoretical 1/sqrt(N) reduction (predicted 8.68 and 4.34 respectively against the measured 8.71 and 4.43), confirming independent noise averages out while the shared eye structure is preserved.

Application -- subtraction: change / motion detection between two frames. Using a genuine same-subject pair (subject s0031, open vs. closed eye) rather than a synthetic pair, |A - B| produces a change map with mean intensity 21.13 and peak 100, concentrated exactly on the eyelid/pupil region that moved between the two frames (Figure 11) -- the mechanism a real blink/drowsiness-onset detector would exploit.

Application -- addition: brightness boost / overlay compositing. Blending the original with a gamma-brightened copy (0.5*orig + 0.5*bright) lifts the mean from 101.17 to 129.94 while keeping some of the original's contrast structure (unlike a flat scalar add); a plain constant add (+40) lifts the mean further to 141.17 but shifts every pixel equally, including ones already near 255 (clipping risk).

good_lighting → histogram equalization (score 1.236): despite the "good lighting" label this crop has the lowest native contrast of the three (std 18.4, typical for these low-dynamic-range IR sensor crops), so full-range equalization has the most headroom to gain relative to the noise it introduces.

glasses_reflection → histogram equalization (score 1.206): the glare patch saturates a chunk of the histogram near 255, leaving equalization a large low/mid-intensity region to redistribute; it extracts the most contrast (3.36x) per unit of amplified noise of any technique here.
Negative always scores exactly 1.000: negating a uint8 image flips intensities but leaves both the standard deviation (contrast) and the median-filter residual (noise proxy) numerically unchanged, so it can never win or lose on this metric -- it only affects brightness/polarity, not spread.

Observations & Applications
  • Negative: flips polarity (bright pupil-reflection glints become dark, dark iris becomes bright); contrast and noise are provably unchanged (see Table above) -- useful mainly for visual inspection of dark structures against a bright IR glare, not for downstream thresholding as implemented here.
  • Log transform: compresses the dynamic range, brightening dark regions strongly while compressing bright ones -- on these already-fairly-dark IR crops it raises the mean a lot (e.g. 101→234 on good_lighting) but lowers contrast and noise, since it squashes the bright end where most of the useful pupil/iris edge contrast lives. Least useful of the five techniques on this dataset by the contrast-gain/noise-gain score on all 3 images.
  • Gamma correction: gamma<1 (0.5) brightens shadows; gamma>1 (1.5) darkens and mildly boosts local contrast in already-bright regions. Neither extreme wins outright here, but gamma is the only technique with a single continuously-tunable knob for a user who wants a specific, moderate brightness target rather than the two aggressive-contrast techniques.
  • Contrast stretching: a robust, tunable percentile clip; wins outright on poor_lighting where the native histogram already spans a wide range and equalization's extra aggressiveness buys little beyond what clipping already captures.
  • Histogram equalization: the strongest and most consistent contrast booster (3-4x std-dev on all 3 images, Table in Output), at the cost of the largest noise-proxy increase of any technique (up to 3.24x) -- wins on 2 of 3 images here specifically because these IR crops start with such low native contrast that the contrast gain outpaces the noise cost.
  • Image addition: brightness boost / overlay compositing (e.g. blending two exposures, or lifting shadow detail without a full gamma correction).
  • Image subtraction: change / motion detection between frames -- directly demonstrated on a genuine open-vs-closed pair from the same subject (Figure 11), the mechanism a temporal blink/drowsiness detector would use.
  • Image averaging: noise reduction across repeated acquisitions of the same scene; confirmed to track the theoretical 1/sqrt(N) noise reduction (Output section).
Challenges Faced
  • Log-transform scaling on already-dark IR crops: with a fixed constant c, log transform either did almost nothing visible (small c) or blew the image out to near-white (large c); resolved by auto-deriving c from each image's own peak intensity (c = 255/log(1+max(r))).
  • Histogram equalization amplifying sensor noise and IR glare: the noise proxy roughly triples on all three images after equalization (e.g. glasses_reflection 1.70→4.74) -- the same full-range stretch that fixes low native contrast also stretches whatever impulse/sensor noise and glare-edge artifacts were already present.
  • Small image size (67-172px across the curated sample) limits contrast-stretch headroom: a ~100px crop has far fewer samples per intensity bin than a full-resolution photo, so percentile clipping (2nd/98th) is noisier and less stable, and had to be checked against the actual min/max per image rather than assumed.
  • No true multi-frame burst of the same eye in this dataset: the averaging-for-noise- reduction demo needed seeded synthetic noisy copies of a single frame rather than real sequential frames; the subtraction demo instead used a genuine same-subject open/closed pair (subject s0031) so at least one arithmetic demo runs on two real acquisitions.
  • Building a repeating letterhead/border/page-number in a Chrome-headless-only PDF pipeline (no pandoc/LaTeX available): position:fixed elements in Chrome's print-to-pdf render offset by the @page margin box rather than the true page edge, and there is no native per-page auto-incrementing page counter outside CSS Paged-Media margin boxes (which Chrome's print engine does not implement). Resolved with a <table> whose <thead>/<tfoot> natively repeat every page at print fragmentation, plus a small script that measures the rendered header/footer height and injects absolutely-positioned, sequentially-numbered "Page N of M" markers into the flowing content at computed offsets -- calibrated empirically against the actual rendered PDF.
Conclusion

All eight sub-tasks were implemented in src/enhancement.py and exercised on three dataset images spanning good lighting, poor lighting, and eyeglasses+reflection conditions. Histogram equalization was the strongest single contrast booster (3-4x std-dev) and won the measured contrast-gain-per-noise-gain comparison on 2 of the 3 images (good_lighting, glasses_reflection), while contrast stretching won on poor_lighting, where the native histogram was already comparatively wide and full equalization's extra noise cost was not repaid by a matching extra contrast gain -- i.e. no single technique is universally best; the right choice depends on how much native contrast headroom the specific image already has. The negative transform was confirmed to leave contrast and noise mathematically unchanged (it only flips brightness/polarity). The own histogram-equalization implementation matched cv2.equalizeHist exactly (0 pixel difference) on all three images. Image averaging reduced the noise proxy in line with the theoretical 1/sqrt(N) prediction, and image subtraction on a genuine same-subject open/closed pair cleanly isolated the eyelid region that changed -- the mechanism a real blink/drowsiness-onset detector would use.
